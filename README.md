# ControllerCounter

Windows Forms (.NET Framework 4.7.2) の入力カウンターです。起動中のキー入力、左右クリック、ホイール、通常マウス移動、ドラッグを計測します。

## 自動記録と履歴

- 起動中、30秒ごとに前回保存からの増分を自動記録します。終了時には30秒未満の残りも保存します。
- 保存先: `%LOCALAPPDATA%\ControllerCounter\History\yyyy-MM-dd.csv`。日別のCSVとして残り、アプリの再起動後も参照できます。削除するまで保存されます。
- 「今回の入力」は起動後の累計、「履歴・推移」は保存済みの活動量です。既存のCSV読込は今回の累計だけを置き換え、過去の活動として二重計上しません。
- 期間は過去10分・1時間・6時間・24時間・7日・30日、集計単位は1分・5分・15分・30分・1時間・3時間・5時間・8時間・1日から選べます。
- 表には各項目と総入力距離、下部には選択期間の合計を表示します。分・時・日の区切りは端末のローカル時刻です。
- グラフは1つだけ表示します。右上の選択欄で対象項目と「折れ線グラフ／横棒グラフ／縦棒グラフ」を切り替えます（初期表示は横棒）。縦軸は時刻で上から古い順、横軸はその区間の入力数・距離です。記録のない区間はグラフ上だけ0として点を補い、折れ線をつなぎます。縦棒グラフでは横軸が時刻（左から古い順）、縦軸が量になり、横スクロールで確認できます。
- 「時間目盛りの間隔(px)」は4～200で調節できます。集計単位が1分なら1分目と2分目、1時間なら1時間目と2時間目の上下方向の距離が指定した幅になります（縦棒では横方向）。表示範囲に収まらない部分は縦スクロールで確認できます。表示は最初の記録から始まり、最新の記録までスクロールできます。目盛りラベルは重ならないよう間引きます。
- 右上の「区間の量／期間内の累計」で値の表示方法を選べます。累計は選択期間の最初の記録から加算し、期間外の記録を含みません。折れ線・横棒・縦棒で利用できます。項目を「総入力距離」にすると各入力を換算した距離の累計になります。期間を変えると累計もその期間内で計算し直します。履歴表は区間ごとの値を維持します。
- グラフと履歴表の境界線をドラッグすると、両者の表示領域を変更できます。
- 「履歴表の表示項目」のチェックを外すと、その項目の表の列だけを非表示にします。グラフの対象項目は右上で独立して選択できます。日時列は常に表示します。表示の切り替えは記録・集計や保存済みデータには影響しません。表示設定は自動保存し、次回起動時に復元します。
- サンプルは保存時刻の区間へ計上します。境界をまたぐ30秒間の量は保存時刻側に含まれます。記録がない期間は表では空白のままです。グラフでは表示上0として補完します。
- 保存失敗時は画面下部にエラーを表示し、次回に未保存分を再試行します。強制終了では最後の保存後の入力が失われます。停止中・スリープ中の入力は記録できません。
- 総入力距離は従来の換算（キー・クリック各1m、ホイール0.5m、マウスは96 DPI換算）です。入力したキーの文字内容は記録しません。アプリ名とウィンドウタイトルは作品別の絞り込みのために記録します。

## 開発・検証

Windows: Visual Studio の .NET デスクトップ開発と .NET Framework 4.7.2 ターゲットパックを用意し、`ControllerCounter.sln` をビルドします。

このクラウド環境では次でクロスビルドできます。

```sh
bash /workspace/tools/controllercounter/build.sh Debug
bash /workspace/tools/controllercounter/build.sh Release
```

履歴の保存・読込・時間集計のテスト（.NET 8 SDK）:

```sh
/workspace/tools/controllercounter/dotnet/dotnet run --project tests/HistoryTests.csproj
```

GUIとWindows入力フックはWindows上で確認してください。30秒待った後の記録、再起動後の履歴、期間・単位の切替、右上の項目選択、折れ線／横棒の切替、時間行間隔の最小・最大値と縦スクロール、境界線のドラッグ、表だけに作用する各チェックボックスの切替（全解除・再表示も含む）、CSV読込前後の重複がないこと、終了時の保存を確認します。


## 描画の回帰確認（Windows）

行間隔を縮めた際の見出し・棒の残像を防ぐため、グラフはネイティブの `AutoScroll` による画素移動を使わず、専用スクロールバーの位置から毎回描画します。部分再描画では元のクリップ領域を維持し、見出しや軸などの領域へ描き出さないようにしています。

Windows の Visual Studio 開発者コマンドプロンプトで次を実行できます。

```bat
msbuild tests\ChartRenderingTests.csproj /t:Build
tests\bin\ChartRendering\ChartRenderingTests.exe
```

このテストは実際の描画処理を使い、行間隔40→12→8→4→200→4、複数のスクロール位置、折れ線・横棒・縦棒と区間値・累計の各組合せで、部分描画が指定領域からはみ出さないことを確認します。入力フックや自動記録は起動しません。テスト用のウィンドウが開くため、Windowsのデスクトップ環境で実行してください。Linux環境ではビルドのみ確認可能です。

実画面では、スクロールした状態で行間隔を縮める／広げる、ウィンドウをリサイズする、グラフの種類を切り替える操作を繰り返し、見出しが上部の1つだけであること、軸や棒に残像がないことを確認します。


## サイズ変更時の負荷対策

グラフの値・累計・最大値は履歴更新時だけ計算し、描画時には再集計しません。二分探索で表示範囲を選び、その範囲と折れ線の接続に必要な前後の点だけを描画します。表は仮想モードで表示セルの値だけを取得します。スクロール範囲も変更があるプロパティだけを更新します。

履歴テストでは30日分の1分データ43,200件に対して、60分の表示範囲の候補が63件に絞られることと、期間を変更した際の累計のリセットを検証します。Windowsでは履歴が多い状態での連続リサイズ、スクロール、グラフ種類と累計モードの切替も確認してください。


ウィンドウ枠のドラッグ中は、グラフ・履歴表の描画とドッキングのレイアウトを停止します。トップレベルのウィンドウには `WM_SETREDRAW` を送らず、可視状態とタスクバーの表示を維持します。マウスを離した後にレイアウトを確定し、全体を描き直します。入力の計測と30秒ごとのファイル保存は継続し、表示更新・履歴の読込と再集計はドラッグ終了時にまとめて実行します。ドラッグ中は内容が追従しません。最大化など通常のサイズ変更は従来どおり描画します。


右端のドラッグ中にタスクバーのアプリ表示が消える問題は、トップレベルウィンドウへの `WM_SETREDRAW(false)` が `WS_VISIBLE` を一時的に外す副作用によるものです。この命令の使用を廃止し、グラフ・表の `OnPaint` / `OnPaintBackground` をドラッグ中だけ抑制します。ビルドや再起動を行う処理ではありません。Windows用テストにはドラッグ開始・終了時のネイティブ可視状態とウィンドウハンドルの維持確認を追加しています。


## 数値目盛りと表示設定の保存

「数値目盛り: 自動」のチェックを外し、「数値の刻み」で補助線の値の間隔を指定できます。例えばドラッグ距離を1m刻みにすると、数値軸と補助線は0・1・2・3…mになります。0.001～1,000,000,000の範囲で指定でき、自動／手動と刻みはグラフの項目ごとに記憶します。横棒・折れ線では横軸、縦棒では縦軸に適用し、累計表示でも利用できます。

「数値上限: 自動」と「数値目盛り: 自動」は別々の設定です。刻みを変えても上限・縮尺は変わりません。たとえば両方の自動チェックを外して「数値の上限」を50、「数値の刻み」を1にすると、右端50のまま1刻みの補助線を引きます。上限を自動にした場合はデータから丸めた上限を決め、目盛り自動では従来より細かい補助線を表示します（ラベルは小数第1位まで）。固定上限をデータが超えたときは全データを表示するよう上限を拡張し、見出しに表示します。上限と刻みは項目ごとに保存します。補助線が密集するほど細かい設定では、操作負荷を抑えるため刻みの倍数で間引き、見出しに「数値目盛りを間引き表示」と表示します。数値ラベルも重ならない範囲で表示します。

履歴の期間、集計単位、グラフの項目・種類、区間／累計、時間目盛りの間隔、履歴表の表示列、項目ごとの数値目盛り設定を `%LOCALAPPDATA%\ControllerCounter\view-settings.xml` に自動保存します。操作後0.5秒と正常終了時に保存し、次回起動時に復元します。ファイルが破損した場合は初期値で起動し、読込・保存に失敗した場合は履歴画面に警告を表示します。入力履歴のCSVとは別のファイルです。


## 最後の時刻を上端へスクロール

グラフ末尾には、最後の時間行を表示領域の一番上まで移動できるだけの余白を確保しています。最後の行が最上段に来た位置で止まり、それ以降はスクロールできません。横方向に時間が並ぶ縦棒グラフでも、最後の時刻を左端の行まで移動できます。余白は追加の記録や将来のデータを意味しません。表示範囲・時間目盛りの間隔に応じて上限を更新し、ウィンドウを大きくしても末尾位置を維持します。


## アプリ・作品別の記録とフィルター

入力発生時にアプリのプロセス名とウィンドウタイトルを取得し、30秒ごとにウィンドウ別の活動量を保存します。キーボードは前面ウィンドウ、クリック・通常のマウス移動・ホイールはカーソル位置のウィンドウに振り分けます。ドラッグ距離は左ボタンを押した時のウィンドウに加算し、途中で別のウィンドウへ出ても帰属を変えません。高頻度のマウス移動ではタイトルを最大100msキャッシュします。

履歴画面の「アプリ」「作品名／タイトル」で絞り込めます。どちらも大文字小文字を区別しない部分一致で、空欄なら制限なしです。候補一覧は選択期間の記録から表示します。作品名だけを入力すれば、アプリ名や未保存表示（*）などタイトルの違いをまたいで絞れます。表・グラフ・期間内累計・下部の合計に同じ条件を適用します。「絞込解除」で全記録へ戻せます。入力した条件は表示設定に自動保存し、次回起動時にも復元します。

作品名はウィンドウタイトルに表示されている文字列から扱います。CLIP STUDIO PAINTなどでタイトルに作品名が出ていない場合や、別のダイアログのタイトルになっている場合は、その時点で取得できたタイトルを記録します。作品ファイルの内容を読み取ったり、ウィンドウに表示されない作品名を推測したりはしません。タイトルには他のアプリの文書名・ページ名なども含まれます。保存先はローカルのみです。

新しい記録は `%LOCALAPPDATA%\ControllerCounter\History\Windows\yyyy-MM-dd.csv` に保存します。既存の `History\yyyy-MM-dd.csv` は変更せず、全体表示で引き続き読み込みます。過去の記録にはアプリ・作品情報がないため、作品名やアプリを指定した絞り込みには含めません。作品別の記録はこの変更後に発生した操作から利用できます。1回の保存で複数ウィンドウを操作していれば複数行になります。タイトル文字列も保存するため、以前の数値だけの履歴より容量は増えます。従来の「CSV出力／読み込み」は今回の累計値を扱い、作品別履歴のインポート・エクスポートではありません。

Windowsでの確認項目: 異なる作品A/Bを開いて操作し、それぞれのキー・クリック・ドラッグが分かれること、Aで始めたドラッグを別ウィンドウへ動かしてもAに残ること、30秒後に両作品を絞り込めること、再起動後もフィルターが復元されること、旧履歴は全体表示に残ることを確認してください。


## 0の区間と累計の折れ線

選択期間に存在する履歴の最初から最後まで、集計単位ごとの点をグラフ上で補います。対象作品の記録がない時間帯も、区間表示は0、累計表示は直前の合計を維持して折れ線をつなぎます。フィルターに一致する記録がなくても、他の記録がある時間範囲には0の点を表示します。期間内に履歴自体がない場合はグラフを表示しません。補完点は表示用であり、履歴表への行追加・ファイル保存・入力量の加算はしません。アプリ停止中など実際には未計測だった時間も、グラフ上では記録量0として表現します。
